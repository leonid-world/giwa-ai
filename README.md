# MidProof · 비공개 재무 검증

가상 기업의 재무값으로 실제 Midnight ZK 증명을 생성하고, 상대방에게는
요청한 기준의 충족 여부만 보여주는 해커톤 데모입니다. 확인 기관도 가상이며
은행 검증이나 실제 대출 심사가 아닙니다. GASOK의 기존 매출채권 흐름과
Midnight PoC를 재사용하고 있습니다.

## 공개 데모

[데모 열기 — giwa-ui.vercel.app](https://giwa-ui.vercel.app)

로컬 서버를 켜지 않고 브라우저에서 이용할 수 있습니다. 데모 화면과 통합
서버가 기존 Vercel·Railway에 배포되어 있습니다.

1. **검증 요청자**로 로그인 → **재무 ZK 검증**에서 기존 결과를 확인하거나
   검증 요청을 만듭니다.
2. **판매기업** 또는 **구매기업**으로 로그인 → **받은 요청**에서 가상 재무
   시나리오를 선택하고 해당 회사의 MetaMask 지갑으로 동의합니다.
3. **검증 요청자**의 보낸 요청에서 기준 충족 여부를 확인합니다.

기존 완료 결과는 지갑 서명 없이 조회할 수 있습니다. 새 증명에는 당사자
지갑이 필요하며, MetaMask의 이 사이트 연결 허용과 새 요청에 대한 서명은
사용자가 직접 진행합니다.

데모 계정과 기존 테스트 채권은 준비되어 있습니다. 계정은 공유용이므로 실제
개인정보를 넣지 않습니다. 재무 시나리오는 서버 안에서 정해진 가상값으로
구성되며 임의의 실제 재무정보는 받지 않습니다. 증명 서버 운영자는 가상
재무값을 처리할 수 있습니다.

## 소액 채권 테스트

새 채권은 **채권 1,000 / 펀딩 900 mKRW**로 시작하며, 최대 **10,000 mKRW**입니다.
펀딩은 채권액 이하, 상환은 채권 원금 전액입니다. 금액은 1 mKRW 단위로 입력합니다.
과거 고액 채권은 기록을 보존하며, 소액 테스트에는 새 채권을 발행하세요.
새 빈 환경은 데모 계정만 준비하고 화면에서 새 채권을 발행하도록 시작합니다.
가상 연매출·부채비율 등 ZK 검증 데이터는 이 채권 금액과 별개입니다.

## 로컬 개발

현재 로컬 이관본과 Railway는 같은 Midnight 지갑·상태를 사용합니다.
**Railway가 가동 중일 때 이관본으로 로컬 Run을 실행하지 마세요.**
서로 다른 호스트에서 동시에 쓰면 지갑 상태가 충돌할 수 있으며, 호스트 간
동시 실행 방지는 아직 구현하지 않았습니다.

1. Java 17, Node 22, Docker Desktop이 설치되어 있어야 합니다.
2. IntelliJ에서 **Midnight Demo** 실행 구성을 선택하고 **Run**을 누릅니다.
3. 프론트를 열고 **검증 요청자**, **판매기업**, **구매기업** 중 역할을 선택합니다.

DB, 증명 서버, 가상 확인 기관, 증명 처리와 결과 조회는 자동으로 시작됩니다.
Midnight Node와 Indexer는 공용 Preview를 사용합니다. 별도 터미널에서
각 서버를 실행할 필요가 없습니다. Stop 후 다시 Run해도 데모 상태를 유지합니다.
macOS에서는 Docker Desktop이 꺼져 있으면 자동으로 켜서 준비를 기다립니다.
검증한 로컬 환경에서는 최초 동기화 약 9분, 저장본을 이용한 재실행은
27초 안에 준비 완료를 확인했습니다. 네트워크와 PC에 따라 달라질 수 있습니다.

프론트 로컬 개발은 `giwa-ui`에서 `npm ci`, `npm run dev`로 실행합니다.
통합 API 주소는 `http://localhost:18080`이며, 배포된 프론트는 기존 Vercel을
사용합니다. 최초 다운로드와 Preview 동기화에는 시간이 걸릴 수 있습니다.

새 환경의 Preview 지갑에는 최초 한 번 무료 테스트 토큰이 필요합니다.
준비 상태와 공개 지갑 주소는 API의 `/midnight-proof/v2/demo/config`에서
확인할 수 있습니다. 지급 후 지갑·계약·확인 기관 준비를 자동으로 이어갑니다.

## 배포

**Vercel 1개 + 기존 Railway 프로젝트 1개**를 유지합니다. Railway에는
통합 앱과 기존 MySQL, 총 2개 서비스가 있습니다. 가상 확인 기관·증명 서버를
별도 서비스로 배포하지 않습니다. 현재 공개 서버의 증명 준비 완료와 기존
결과 조회를 확인했습니다. 이후 백엔드 변경은 GASOK 루트에서 기존 Railway
앱으로 CLI 업로드 한 번으로 배포합니다.

설정과 기존 서비스로 배포하는 명령은 [배포 안내](docs/ai/DEPLOYMENT.md)에 있습니다.
현재 검증 범위와 외부 준비 사항은 [현재 상태](docs/ai/CONTEXT.md), 제출까지
남은 일은 [체크리스트](docs/ai/TODO.md)를 참고하세요. 빌드 성공과 실제 체인에서의
전체 데모 성공은 별도로 기록합니다.

현재 루트와 각 서브모듈의 작업 브랜치는 `giwa-midnight`입니다. 소스를 받을 때는
서브모듈도 함께 받아야 합니다. 기존 GASOK `main` 제출 이력과 GIWA 계약은 보존합니다.
Midnight는 Preview만 사용하며 Preprod와 Mainnet에는 배포하지 않습니다.
